# 资料四级分类与回执规则

适用系统版本：2.8.0 · 文档修订：2026-10-18

## 先知道何时分类
新建或导入资料、正文/主要用途实质变化、收到专项治理任务时进行评定。普通读取、改名、存储迁移和调用次数增长不要求重新评定。
批量导入可先保存再补评；不让分类阻塞原件存取。内容不足时保持“未评定”，注明阅读覆盖；它是待处理状态，不是第五个等级。
阶段结束检查本阶段需要评定的资料，避免让治理挤掉实际业务。

## 标准及例子
|级别|标准|例子与判断边界|评定者|
|---|---|---|---|
|特级|明确指定的核心或特别留存资料|指定核心说明书、总体中枢架构；不根据名称自动授予|组织/项目管理人按明确人工指令指定|
|一级|帮助理解整体项目进度、核心架构和主要最新成果|真实总进度报告、核心架构决定、主要成果及解释；零散新文件不因“最新”自动升级|Agent自主判断|
|二级|正常业务资料，支撑具体工作、参考和追溯|普通会议、研究材料、过程稿、局部回执；关键会议可一级|Agent自主判断|
|三级|主要承担备份、维护和历史留存用途|独立备份资料、重复维护日志、合成通路样例；不是自动删除的依据|Agent自主判断|

按实际内容、项目用途和阅读证据分析，留一句理由，不采用机械打分或固定标题匹配。历史关键依据可继续一级，未读资料不冒称理解。
原件有备份不意味原件降级。存储副本与逻辑资料不同；不为分类重复创建同一份原件。
特级由人工指定，普通治理不能撤销或降级。只有管理人根据新的明确指令通过专用接口调整。

## 与存储、权限和简介的关系
重要性与物理存储独立；具体归档、使用计数、恢复及副本清理规则统一见material-storage。
特级沿用一级的兼容索引资格，但通过独立人工指定记录显示为特级。指定特级由周期维护保持标准；物理恢复有等待，以实际状态为准。
特级、一级、二级可建立Agent简介向量；三级不新增简介向量。简介缺失不阻塞原件存取。
分级不会改变项目权限、可见范围或当前软件能力。

## 实际调用
1. 使用hub.tools按“资料与分类”功能组取得工具，再用tool选择读取完整契约；hub.invoke按真实工具名调用。
2. 普通评级用hub.material.attributes的importance_level（1/2/3）和reason；扩展属性保存用途、reading_coverage等。也可以沿用hub.material.govern，但物理存储变化需看实际结果。
3. 人工特级用hub.material.designate：material_id、special:true/false、human_instruction、idempotency_key；可显式expected_revision，撤销时importance_level指定恢复级别。专用服务要求当前项目管理权及现行mem.write资格。
4. API等价入口：hub2_api，system:meng，POST /v2/materials/importance-designate；body还需project_id和expected_revision。
5. 返回core.importance_class为special/1/2/3，core.importance_level保持兼容数值1/2/3。手动指定对象身份和版本不变。
人工指令文本是管理端声明并留痕，不是宿主已证明“人类当场点击”的证明；Agent只在收到明确指令后使用专用入口。不要用自填来源字段冒充授权。
通用metadata接口不能伪造或删除special_designation记录。原接口仍可改其他属性；试图降级特级会拒绝。

## 阶段报告与回执清单
沿用原有：对话/项目/工作关联、目标与实际完成、判断和依据、不确定性、成果固定引用、原文引用及覆盖、未解决事项和下一步。
增加“本阶段资料治理”：仅列本次新增/实质更新或专项处理的资料引用、等级、简短理由、是否实际写入，以及待评/待补事项。
已有评级记录引用即可，不复制全量属性；无治理变化可省略，不新建重复回执。
报告、原文、成果分别保存。失败保持原提交标识等待补报，不能把建议或接口存在写成已完成操作。

## 简短行为示例
形成项目整体进度报告→评一级并记录理由→保存正文和等级→在本阶段回执关联结果。
普通查资料→沿用已有评级→按需读取，不扫描全库重评。
内容未读懂→先保留原件、标待评及阅读覆盖。
人工指定说明书特级→专用接口留存指定→确认importance_class:special→普通Agent维护内容时保留指定。

历史版本与变更记录保存在正式发布档案；通过 POST /v2/manuals/read 提供本篇 id 和指定 version 可读取对应冻结正文。
