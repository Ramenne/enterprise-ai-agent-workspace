# 资料存储服务 · 文件、属性、关系与存储

适用系统版本：2.10.0 · 文档修订：2026-10-21

## 数据组织
对象存储保存资料本体，PostgreSQL保存材料身份、固定版本、存储副本、属性、来源与事件。文件不是只能落在唯一目录中的树节点。
material_id为稳定UUID；file_no为数据库唯一递增BIGINT可读别名，当前序列从1000000开始，不固定7位，也不是数学上无限。
内容版本有稳定version_id；current_version_id指向当前版本，历史引用保持当时版本。平台同时返回file_display_no（如F-1001300）、local_version_no（文件内固定版本序号）和display_no（如F-1001300-001）。本地版本序号与文件内首次建立的固定版本绑定，切换当前版本不重编号；序号超过999继续完整显示。工作编号与文件编号分属不同类型。

API：`hub2_api({system:"meng",method:"POST",path:"/v2/materials/by-number",body:{number:"F-1001300-001"}})`。F-文件号定位当前有权版本，带版本序号定位指定固定版本；旧数字、#数字及原UUID格式继续按当前帮助兼容。返回受当前权限过滤，不要求手填hash；保留工具返回的fixed_ref用于后续读取和采用。统一MCP现已登记`hub.file.find`；具体字段仍读实时`hub.tools`/`hub.help`，保留当前权限与固定版本。

## 名称与属性
名称保留文件扩展名。数字编号不编码项目、重要性或负责人，避免属性变化就改身份。
系统固定信息：稳定ID、数字编号、版本、状态、大小/类型、权限项目、重要性、创建/变化记录。
扩展信息：properties中的JSONB；attributes保存类别、相关项目、用途、阶段、语言等有价值属性，按实际需要扩展，不限少量。
命名建议使用明确snake_case键、稳定枚举与单位；这是约定，不虚构系统已对所有自定义键完成强制规范化。
file_format后端缓存可来自扩展名推断或人工/Agent声明，不等于内容识别证明。页面不重复强调名称中已经体现的格式。

## 权限项目与关系
文件的权限项目是服务校验范围，不能通过随意写一个project标签授予读取权限。
相关项目属性可多值，用于定位；真正采用、工作关系和依据由V8记录。
actual_inputs及来源边记录实际派生来源。项目共同归属不会自动证明文档互相引用，也不会自动生成所有间接关系。
个人分享可使用当前sharing/disclosure能力；个人转团队属于项目与权限变化，需对应资格，不能只改标签。

## 重要性与实际存储
|级别|含义|物理存储|简介向量|
|---|---|---|---|
|特级|人工明确指定核心/特别留存|默认保持标准|可建立|
|1|整体进度、核心架构、主要成果|按14天/3次规则|可建立|
|2|正常业务资料|按14天/3次规则|可建立|
|3|备份与维护留存|按14天/3次规则|不新建|

评级不会直接搬迁资料，也不因调用频次自动升降级。标准读取、归档存储与取回仍可能产生云端费用；恢复可能需要等待。

## 三级搜索
普通 `mem.search` / `POST /v2/materials/search` 在提供 query 时，自动先查名称等固定属性，再按显式 properties 查 JSONB 扩展属性；定位不足才调用现有简介 BGE 向量服务。无 query 的原列表/属性过滤调用保持兼容。
不是“返回了文件就停止”：稳定编号、非截断结果中唯一精确文件名、或不带自由文本的唯一明确属性约束可定位；宽泛问题、同名或截断候选继续向下，最终语义候选返回 needs_selection，不伪称已经找到正确文件。没有扩展属性条件时该层明确 skipped_no_constraints，不凭空编造属性。
高级入口 `POST /v2/materials/retrieve` 参数 project_id、query/name/number、properties、limit、candidate_limit，以及 version_created_after/version_created_before。时间指当前或指定固定版本的创建时间，为各层硬筛选；不是文件最初创建时间，也不以最新替代相关性。编号指定历史版本时不换为新版本。properties 示例：`{"attributes":{"material_kind":"系统使用说明"}}`。
候选保留当前权限、来源闭包与固定版本校验。返回 stages、resolution、located_by、items、coverage。candidate_limit 默认50、最多100，是有界搜索而非全库枚举；简介/原件没有被自动采用。
向量兜底后使用标准 BM25 长度归一与加权 RRF 融合名称/简介词项排序和 BGE 排序，RRF常数60，语义/词项权重2:1。不是新训练的模型或神经重排器，也不保证每个问法都正确排首位。真实帮助：`GET /v2/materials/search-help`。

## Agent 简介规范与自动索引
简介仍由 Agent 或成员依据固定原文撰写，系统不自动读全文生成。写明材料主题与类型、主要内容、用途及可回答的问题、适用范围和必要局限；未完整阅读须声明覆盖。通常80至250汉字，短材料可更短，最终以模型512 token实际检查为准。
不编造原文未包含的主题、结论和采用关系，不堆砌某条查询的关键词，不同主题不复制套话，不用“已登记/已上传/已保存”充当正文简介。active的空简介或纯流程占位会拒绝；其他长度和内容完整性给维护提示，程序不宣称能够自动证明语义真实。
active简介保存后沿同一成员和当前资格自动尝试索引，仅嵌入简介；权限不足、模型不可用、超长、并发改版等状态明确返回，不撤销已保存简介、不阻塞原件。草稿/撤回简介不自动索引。缺简介仍可属性检索。规范接口 `GET /v2/materials/description-policy`，版本 agent-description-v1。

## 常用接口
attributes、usage、by-number、usage-candidates，及write_text、metadata.patch、enumerate/page、search、head/history、description.save/read/pending、semantic.query/index_fixed。
集合(collection)和logical_path是组织视图，不单独授予权限。大文件使用上传票据、分片、暂存或认证流式读取；不把简易网页上传上限当作系统容量上限。

## 使用与变更
更新正文携带当前基版，产生新的固定版本；修改属性保持内容身份。冲突时保存候选并恢复原操作，不丢失双方工作。
使用事件记录读取/采用/再用，历史覆盖从相关采集能力上线起算。请求字段统计不等于Agent内部实际理解或每个字段都被使用。
恢复、纠正、等价关联、垃圾回收和补偿有独立接口；永久删除仍需实际范围与引用检查，目录消失不代表对象已销毁。仅授权指定文件时按该完整资源校验，不扩大为整项目权限；资料移项后旧范围失效，固定版本与SHA保持，读取仍须当前范围有权。

## 四级标准与人工指定
详细标准、评定时机及回执规则见material-classification。core.importance_class展示special/1/2/3，importance_level保留兼容数值；特级通过独立special_designation记录表示。人工指定需项目管理权及明确指令声明，普通评级不能撤销或降级。
使用hub.material.designate或POST /v2/materials/importance-designate；普通一级至三级继续原工具。指定不改变文件身份、权限或物理存储。

## 可选加工与失败恢复
普通文字保存已经声明与加工输入一致的直接来源时，可以继续通过processing.finish完成原加工；不同来源仍拒绝，不悄改来源。
同一run/attempt/outputs的加工完成重放返回既有结果，不重复效果。文件冲突保留原正文草稿，可显式另存候选，当前正文与旧采用不被自动覆盖。

## 文件管理与清理制度

物理存储采用标准与归档两层。兼容请求的具体行为由存储接口契约说明。
普通资料连续14天没有正文读取、明确采用或复用时转归档；新正文版本和真实回标准后的保留期按相应有效活动计算。原生版本无使用历史时以创建时间兜底；受控迁入旧文件保留可信原源最后调用时间，没有源调用时用原源创建时间，不把迁入时间当作新使用。已识别旧文件连源时间也缺失时明确待补，不伪造导入前调用。可信源时钟由受控源台账维护，普通可改属性不能写入该事实。
归档后累计3次独立有效使用转回标准存储，计数从本次归档起算；列表、搜索候选、元数据查询、迁移校验、恢复轮询不计入。按既有幂等使用事件计数，同一事件重试不累计。分级与存储独立，频次不改变重要性。
特级及显式 `properties.storage_policy.keep_standard:true` 的资料保持标准层；普通一级至三级遵循同一闲置规则。人工指定特级仍保留专用权限与明确指令要求。

Mem进程启动后30秒开始检查，此后每小时循环；按项目分批处理、失败沿原操作恢复，当前权限每次重新校验。同项目迁移串行，未知云端效果只查询；明确403拒绝且私有机器记录证明未发生效果时，修正权限后才可重新派发。
读取冷归档遇到需要恢复时自动提出取回并返回 `restore_required`、原固定引用和重读提示；云端等待期间不能报告已读或已回标准。累计3次使用后的回标准也可能等待取回。历史引用、编号、正文hash及版本身份保持。

清理分为三类：读取缓存过期清理；已验证后继副本、且无使用/恢复保护的旧物理副本回收；原件及历史版本的逻辑删除。前两类按实际保护条件执行，进行中的读取保留租约；第三类不由闲置规则触发。归档不是删除，不以改属性冒充搬迁，不把切换成功冒称旧副本已释放。
同一退役操作在派发前重新核对读取租约、恢复保护和固定物理目标。等待期间出现新读取时重新保持held；发布新内容版本不能让旧操作改删新版本。删除只针对已绑定的物理VersionId，原逻辑固定历史保留；未知删除效果先核对原操作，不能自动第二次派发。
当前primary_tier、热副本是否已回收与历史receipt分别读取。旧回暖成功回执不保证现在仍在标准层；状态变化后按当前信息决定新意图。恢复等待保留原operation_id及目标；known_archive_copy_required是409目标/操作条件冲突，应核对该固定版本对应的归档操作而非反复发送原错误请求。

现有评级保留；新建/导入、内容或主要用途实质变化时由Agent或成员依据实际内容评定，保留理由和阅读覆盖。未评定是待处理状态，不能批量猜等级，也不阻塞存取或物理归档。

接口（通过 `hub2_api` 的 `system:"meng"` 调用）：
- `POST /v2/materials/lifecycle/plan`：project_id，limit默认20，after_version_id分页；只返回候选、当前层、目标层、实际使用及规则。
- `POST /v2/materials/lifecycle/run`：相同参数，实际执行候选并逐项报告 copy/restore/switch/retirement 状态。material_id、version_id可缩小本次范围。
- `POST /v2/materials/classification/pending`：project_id，limit默认20，after_file_no分页；返回未评级且有权读取的资料元数据。沿 `hub.material.attributes` 或 `hub.material.govern` 写评级；纯评级不自动选存储层。
- `POST /v2/objects/storage-tier/info`：project_id/material_id/version_id，查询真实当前层与旧副本回收状态。

以上管理仅作用于已选择资料存储服务登记的资料；不接管外围应用自有桶或业务数据库。

## 旧桶固定版本与搜索交付

上海历史源已接入现有归档、取回、回标准与精确物理退役流程。先固定真实bucket/key/VersionId并完整校验源SHA/大小，再COPY；核验预算、读取租约、来源闭包、当前权限和CAS均保留。未知效果沿原operation查询。精确旧版本HEAD404还须后继副本HEAD200作正向控制，才能按已观察缺失补回执，不再盲发删除。
物理引用预筛选使用真实字段和索引，解析器变化回退原全引用扫描，不取消热读取、恢复与来源保护。原最后使用时间与新使用共同参与最终派发校验；不是修改属性冒充归档。
搜索所有提前/最终交付分支统一重新校验当前权限与固定目标，并补足有界可读候选；员工客户端属性查询/已加载窗口对账支持条件未变响应，上传冲突采用与创建相同的by-path。并非放宽权限或无界全库搜索。
执行数量和容量属于当次快照，见工作#1000180：先643个不同固定版本，后原时钟阶段5166个版本约3.64GB；不跨阶段简单相加为去重总数。不代表全账号暂存/备份已清理，部分历史低频旁路副本和受限对象仍待处理。

历史版本与变更记录保存在正式发布档案；通过 POST /v2/manuals/read 提供本篇 id 和指定 version 可读取对应冻结正文。
