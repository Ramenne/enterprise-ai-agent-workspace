# 服务与资产迁移

适用系统版本：2.10.0 · 文档修订：2026-10-21

迁移以现有项目、真实资产和当前执行授权为范围。项目工程沿既有project_id，不为同一工程另建项目或重编资料号。

## 查找当前对象
调用hub.services发现本人可见项目及当前服务观察，再从对应工程status查看实际运行与发布。旧入口、迁入资产位置和历史暂停记录只作为出处，不决定当前服务状态。

## 实施顺序
1. 读取原目标、当前资料位置、实际业务依赖与团队选择的接入范围。
2. 按获准范围准备目标资源，确认源码/数据/对象/身份各自维护方。
3. 迁移后分别核对数据接续、入口、权限和业务效果；代码切换不等于数据库回退。
4. 沿原工作保存原操作、当前结果、未完成项与接续位置。

主控职责见service-boundary；个人测试机和登记工程的维护方式见project-engineering。已停用旧实例不会因资产登记或迁入自动启动。旧ID与新对象映射保持可追溯，当前原件与固定历史不因整理而丢失。

## 历史存储与项目源码交付的当前边界

受控旧源迁入保留真实源时间和精确物理版本，归档/恢复/SHA与逻辑身份保持规则见material-storage。旧源准入修复不扩大为整个桶任意读写。
工具/账号及AI客服源码、拼多多后台源码已按实际授权交付共享Git/固定包，原项目ID、owner及工作历史保留；拼多多与闲鱼账号项目已按用户纠正恢复personal，具体已授成员资格保持。源码可读写、commit与临时merge核验不等于产品部署入口、双向同步或线上业务接管。迁移/交付报告和产品发布必须分开留存。

历史版本与变更记录保存在正式发布档案；通过 POST /v2/manuals/read 提供本篇 id 和指定 version 可读取对应冻结正文。
