## 后端剩余范围

不能把仅有标签的扁平文档列表当作完整知识系统。应在真实后端沿原稳定ID及固定版本逐步补：

- 知识性质（外部参考、项目实践、方法说明）独立于主题分类。
- 存放权限项目沿既有projectId；相关业务项目可多个，不复制主体。平台、场景、用户类型等用少量标签，正文保留具体办法与适用条件。
- 当前有效性独立于research/partial等证据状态。被替代/撤回退出默认有效查询，历史版本继续保留；跨条件并存不武断覆盖。
- 服务端按业务项目、知识性质、标签、有效性有限查询与分页；变化读取需包含归档/撤回并明确游标失效，不用时间戳冒充无遗漏游标。
- 项目接续manifest保留知识版本、来源覆盖及获取/理解/提交边界。继续使用原项目文档即可，不把MCP请求日志当采集进度。

目前未拿到Node知识库源码，因此本阶段不臆造表名或生成不可执行SQL迁移、不改权限、不批量迁移49篇现存文档或108条本地候选。
