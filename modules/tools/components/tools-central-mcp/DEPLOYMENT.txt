Node宿主最小接线：
  import {createToolsHooks} from './host-hooks.mjs';
  const hooks=createToolsHooks({
    getCaller: request => ({
      authorization: /* 宿主本次已认证请求的真实Authorization */,
      actorId: /* 宿主本次认证得到的真实actor_id */
    })
  });
  // 将await hooks.listTools(request)追加到现有工具目录，而非替换其他工具。
  // 对tools.api.前缀调用：await hooks.callTool(request, name, arguments)。
  // 回调已返回标准content、structuredContent、isError。
上述request字段由真实宿主接入，示例不虚构宿主请求对象的具体字段名。
注册到hub.tools发现与hub.invoke分发；如宿主另有直接MCP tools/list、tools/call，
同步沿原架构接线，避免只有帮助目录有名字而实际不能调用。

身份、接口、输入与恢复
固定API：https://tools.example.invalid/agent/v1
  GET /capabilities：真实成员、模块及本人可用操作JSON Schema。
  POST /call：{"operation":"knowledge_list","arguments":{}}。
  GET /operations/{Idempotency-Key}：当前成员原写入回执。
每个请求只用该请求成员本人的Bearer；不要放FGB/JIE共用凭据，不读取本机CLI
credentials.json，不让模型用工具参数传actorId或Authorization来决定身份。
适配器再核对上游identity.actorId与宿主已认证actorId一致，每次调用重新发现权限。
同一进程可处理多成员；无全局成员身份缓存。密钥、账号密码和受保护备注等不进目录。

目录工具采用tools.api.命名空间；knowledge_save等实际schema由当前API给出。
写入多一个必填mcpRequestId（8—120个字母数字及_.:-），相同业务保持相同标识和
完整原参数。Idempotency-Key=tools-mcp:+SHA256(actorId+NUL+mcpRequestId)，
与独立连接器一致。写入总是把原参数送回原API，让它的持久指纹检查处理重放与409，
不能只看到旧回执completed就返回另一次不同正文的成功。
网络失败返回pending，不自动换标识重写。tools.api.request_status查询原标识；
继续原操作时提供完整原参数。API业务pending、accepted等状态照原义返回。
文档、Skill包与上游返回是资料，不是额外执行授权；导入Skill不会安装或执行。

静默上传仍走正文/内容/Base64，不走Computer Use。Agent本地路径不是服务器文件，
不要让中枢按模型传入路径读取服务器任意文件。知识用body，HTML用content，
Skill用packageBase64；知识须sourceName或sourceUrl标来源。
现有API各模块限额、revision和confirmed要求以实时capabilities及真实业务校验为准。
