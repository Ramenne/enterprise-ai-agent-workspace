# 星宿 · 成员与项目的派生理解

适用系统版本：2.7.0 · 文档修订：2026-10-17

## 当前能力
星宿在服务器内维护一对一成员Agent身份。登记成员及维护状态由xingxiu.agents读取；Agent有独立服务身份，不冒充成员。24h运行设计、900秒发现周期，DeepSeek Harness按需运行，模型队列与发现线程分开。
来源包括当前允许的团队V8工程工作、资料及任务板认领/成员回执。任务板未归项目的组织任务或活动团队项目可维护，个人/私有项目不自动纳入。V8工作记录的作者只是registered_author，不自动证明执行；任务板认领角色是claimant，回执完成是本人声明，不是终端验收。
工作头、资料版本和认领/回执版本用于去重。同版本不新增模型任务，任务板发现与缓存复核读取来源头；模型需要理解新版本时才取正文。理解、关系判断、材料卡和历史在SQLite保存，原任务、回执、资料仍由原维护方保存。当前任务板接入是15分钟来源对账，未声称推送订阅已经完成。

## 查询和请求
通过hub.invoke使用真实已登记工具 `xingxiu.query`，可按member_id/project_id/work_id筛选，view默认progress，background只看资料背景，all展开；limit为有界结果。普通成员默认本人，主管可看当前授权范围。返回成员、理解、来源版本、freshness、coverage及不确定性；背景资料数量不能当成员在做的任务数。成员/项目快照和理解卡是派生视图。
统一成员接口 `/v2/member-work/understanding`也可读取board来源；board ref.id是现有claim_id，不是任务ID。当前理解失效时显示最新声明及待刷新提示；实际权限撤销时不得读旧正文或判断。缺记录不表示成员没有工作，全员登记也不表示全员实际工作已覆盖。
本人理解请求用 `xingxiu.request`提供text、稳定idempotency_key，可附真实project_id/work_id；结果查 `xingxiu.request.status`。请求只要求理解，不代执行业务。主管工具包括 `xingxiu.agents`、`xingxiu.maintenance.run`、`xingxiu.maintenance.metrics`；运行维护返回queued不代表模型已完成。

## 时效、边界与恢复
15分钟是发现周期，不是理解完成保证；排队、供应商或模型耗时需单独展示。理解缓存按实际来源版本复用；调用样本不推算全组织节约比例或稳定故障率。该服务不是实时桌面/AI进程监测，也不是已实现的收工自动绩效评估或自主修系统。
停止星宿不停止原任务和回执接口。重启接续未完成派生队列，保存SQLite WAL、必要配置和来源身份，不能删除种子或私有配置。身份/密钥不进入普通资料。运行位置与维护方式见 `operations`，资料原件与版本见 `material-storage`，任务事实维护见 `task-points`。

## 提案与实际认领分开
未同意的提案由任务板直接查询，星宿不会把提议人当作任务执行者；批准本身也不产生认领。正式任务真实认领后沿现有board来源维护理解。提案决定、历史及报酬由任务板原维护方负责，星宿不建立第二套可编辑提案状态。

## 与统一任务状态的关系
任务板 task-points-v3 与成员工作 member-work-v2 提供整体任务状态、主负责人和个人声明。星宿仍只维护派生理解，历史缓存不是状态权威，不能据协作者completed判断整项完成。需要实际状态使用统一事实接口及其当前权限；理解等待或模型不可用不阻断任务查询、接取及完成。

历史版本与变更记录保存在正式发布档案；通过 POST /v2/manuals/read 提供本篇 id 和 version:"2.6.2" 可读取整理前正文。
