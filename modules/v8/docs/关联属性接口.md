# V8 关联属性接口

实现与发布状态以本项目真实工程回执为准。

## 含义与数据来源

关联是对实际使用、承接或回应旧工作的直接引用，由人或Agent判断；同项目、读取过、间接连通不自动成为关联。单一权威仍为 v8.work_relations。属性是既有关系账本的读写表达，不新建第二份JSON关系账本，也不把权限藏进属性。

保存沿用 POST /v2/work-items/save 或 commit（MCP v8.work.save/commit）：

```json
{
  "project_id": "当前项目UUID",
  "work_item_id": "本工作UUID",
  "expected_revision": 8,
  "idempotency_key": "本次追加的稳定提交标识",
  "related_assessment": "partial",
  "properties": {
    "relations": [
      {"work_item_id": "直接引用的旧工作UUID",
       "basis": {"explanation": "本次沿用了该工作确定的存储方案", "refs": []}}
    ]
  }
}
```

UUID由Agent通过已有项目/工作读取取得，用户仍用工作编号。需要时refs填写现有fixed_ref（material_id/version_id/sha256），不填最新模糊地址。新的属性入口需要说明实际用途，旧related入口保持兼容。关联可以为空；是否已判断由related_assessment显式声明，不从空数组自动猜测。属性入口不得与非空related同时提交。schema/project/对象权限、固定版本校验、幂等和CAS仍由既有业务函数处理，不因写属性跳过授权。

服务在决定身份/计算请求摘要之前，把properties.relations归一到原related。relations从properties移除，其他自定义属性保留。归一后的related经同一已有work_save/commit写链进入关系账本，无第二份当前状态。

## 读取与溯源

POST /v2/work-items/read、GET /v2/work-items/:id 和history依旧返回原relations历史及真实coverage；read结果额外提供work_item.properties.relations只读视图：

- outgoing：本工作引用了谁，direction=cites。
- incoming：谁引用了本工作，direction=cited_by。
- 每对工作聚为一个链接，citations保存各条依据及固定文件版本，不把重复关系中的不同理由丢掉。
- 按已返回历史的supersedes收起被替代边；withdrawn不算当前关联；corrected作为新关系版本呈现；原历史不被改写。
- 只使用原work_read已经授权返回的行，不额外查他人项目/正文、不自动传递、不自动共享。
- coverage.complete不高于来源覆盖；缺失前序/不完整历史会明确标注，空列表不冒充全库无关联。

只读属性视图不是写入数组，不能把整个incoming/outgoing视图原样回写。只应追加自己实际判断的新引用，或通过现有supersedes/state写纠正/撤回。无需在阅读或更换Agent时机械重新登记全部关系。

## 数据变更

现有表已经有两端索引、依据JSONB、状态与纠正引用。本轮无DDL、批量数据重写、文件搬动或工作重编号。文件属性/派生来源继续由资料存储服务负责；V8关系中的固定文件引用便于追溯，不等于新造所有文件之间的边。

## 阶段行为

Agent实际使用或回应某个旧工作时顺手保存关联及依据；阶段收口检查遗漏。保存不等待全部评定，未确定关系可以后补。该行为规范不保证未接入的第三方宿主自动执行。

## 验证与发布

定向测试覆盖双向直接引用、无传递、不同依据归拢、纠正/撤回、旧入口兼容、新入口错误拒绝与不完整授权覆盖。构建和测试结果另附真实回执；源码候选不等于已部署。此前related_candidates的internal_error不是本轮属性视图已修复的声明。
