# 员工客户端产品链路与交互

员工客户端是一个产品。动手前找到当前的 `06-个人APP/员工客户端`、`员工客户端-UI设计问题与决策记录.md`、已有稳定组件和对应服务端/连接器 Contract，核对哪些行为已经验证可用。复用行为与视觉规则；场景不同处先明确差异，不复制一套相似但语义不同的流程。

先写一张极短的场景表：用户从哪里进入、想完成什么、哪一步只是暂存、哪一步真正提交、谁拥有权威数据、成功后在哪里看见、失败及重进页面后怎样恢复。不要仅凭按钮名称推断实现，也不要把多个来源相似的操作强行接入同一个中间状态。检查正常路径、窄屏键盘、长内容、重试和页面切换；新增界面复用既有间距、焦点、反馈和弹层规则。

从用户动作倒推结果：入口、确认步骤、可选信息、数据去向、成功回执、重新进入后的状态，以及接收方看到什么。相同文件从不同入口出发可以有不同操作：**协作文件点“发到工作群”应在确认后创建可见群消息；群聊输入栏选文件才进入待发送草稿。**不要把中间态写成“已发送”。重命名只在用户选择更名或保存目标确需命名时出现，转发不强制更名。

文件链以同一个附件身份贯通来源、校验后的应用缓存、个人梦空间、公共群副本、群消息、接收方打开/下载。预览、应用缓存和保存到设备下载目录是不同完成状态；界面应如实区分。图片/视频/音频在可行时使用真正的预览方式；只有完整字节通过校验后才标记可复用。可复用的文件获取应单飞，进度和任务归文件工作流，不归会被路由或消息刷新销毁的卡片。下载、保存、发送和其他页面操作可以并行；明确取消和账号切换才终止对应任务。

验证时用同一个文件走完“预览或获取 → 保存/转发 → 发送回执 → 群聊可见 → 重新进入仍可见 → 打开/下载”，再检查失败、重试、页面切换和不同账号。分别报告源码、本地测试、发布回读、真实手机与接收方验收；前一层通过不能替代后一层。修正用户提出的重复 UI 问题时，把可复用的场景规则和验证结果简要写入员工客户端 UI 经验文档，不堆口号或只记本次执行步骤。

## 六人协作界面与连续使用

员工客户端默认界面服务内部六人的工作协作。工作列表先显示事项标题、可复制编号、中文状态和必要的时间；原始Agent回执、审计语句、调用次数/拒绝码、关系依据和完整历史放明确的展开入口，不用一长段接口原文充当人类工作概览。保留可追溯原件，不编造简写后的业务结论。

把页内导航与启动恢复区分开。点击消息/工作/我的、切项目和打开查找，不应清空已有画面再重复加载。按当前账号保存并共享目录、真实属性、列表和位置；同请求共享执行，已有内容先展示，更新在后台，真实权限拒绝及时隐藏。首次没有数据时如实加载；暂时网络失败走重试/恢复，不展示验证码表单假称登录失效。查询用固定输入入口，属性和值在进入前的目录或快照里已可用，不从当前四个摘要字段假称完整。

“我的项目”包括本人个人项目及本人参与/获授权的团队项目；中枢可读的他人公开personal不是本人的项目。项目卡片直接显示真实归属和实际属性，不能把“可访问”与“我的”混成一组。手机是否保留权限申请按当前用户决定，不能因为API存在就暴露原始JSON页面。

本 skill 不授予上传、发布、发送真实群消息或修改生产数据的权限；这些动作依当前用户授权和项目规则执行。
