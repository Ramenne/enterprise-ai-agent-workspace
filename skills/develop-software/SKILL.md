# 通用软件开发

以当前用户目标和仓库真实状态为准，交付能运行、能验证、边界清楚的软件结果。架构与缺陷正确性优先于形式化留痕。

## 先确定请求类型和权限

- 用户只要求评审、审计、诊断、解释或状态报告时，保持只读；不要自动修复、提交、部署或修改外部系统。
- 用户要求开发、修复、重构、集成或部署时，在明确范围内直接实施，并完成与风险相称的验证。
- commit、push、PR、合并、发布、账号变更、DNS／防火墙变更和生产数据操作，按当前用户授权与仓库规则执行，不从本 Skill 推导额外权限。
- 只修改任务范围内的代码、测试、配置和文档；保留用户已有脏改动，不能处理冲突时再请求裁定。
- 删除、覆盖、迁移生产数据或改变账号／网络可达性前，先确认准确目标、影响和授权。

## 从事实开始，不靠猜测

开始前只读取必要明线：

1. 当前用户任务、Issue 或 PR；
2. 当前目录的 `AGENTS.md`、项目 README 和直接相关的架构说明；
3. 与改动直接相关的代码、Contract、测试、配置和部署材料；
4. 只有涉及 Host、进程、权限、数据迁移或外部服务时，才读取对应边界说明。

发生冲突时依次服从：当前用户最新决定、当前项目规则与策划、当前 Issue／PR、当前代码 Contract、历史文件。旧任务书、评审和证据只提供背景，不能替代当前事实。

普通实现细节在任务范围内合理决定。只有选择会实质改变产品方向、公共架构、Host 边界、账号权限、生产数据或外部可达性时才停下请求裁定。

## 长任务与多 Agent 保持收敛

- 仅当任务预计持续数小时、跨上下文交接或需要多 Agent 协作时，开始实现前固定一份各 Agent 可读取的短基线：目标与非目标、允许写入范围、已定 Contract／关键不变量、验收证据和待裁定项；不强制为普通短任务增加文档或门禁。
- 主控 Agent 负责基线、任务拆分和在当前授权范围内的结果汇总与集成。每个子任务明确输入、输出、允许写入路径、验证要求和禁止改变项；子 Agent 发现跨边界问题时回报，不自行扩大范围或修改公共 Contract。
- 每次交接、上下文压缩、评审和修复都对照同一基线。只有用户的新决定或证据证明原前提错误时才更新基线，并同步所有未完成子任务；不得因局部测试、工具便利或实现惯性暗改目标。
- 需要独立评审时，先固定可识别的候选版本（commit、diff 或等价文件版本）；评审、修复和复核必须指向该候选及其后继，避免在持续变化的工作树上循环判断。
- 长时间无有效进展、连续遇到相同阻断或开始越过路径边界时，主控应停止当前路线，重新检查前提、Contract 和任务拆分；持续等待或增加 Agent 数量不能代替收敛判断。

## 纵向可执行链优先

- 长任务开始时先写出当前阶段唯一的可执行完成线，例如“安装→启动→绑定→读取→持久化→展示”。“生产级”只要求这条当前链达到真实可靠，不等于一次覆盖未来平台、规模和功能。
- 用完成线节点衡量进度，不用提交数、代码行数、Contract 数量或测试数量代替真实能力。每两小时必须形成一次可验证的真实完成线节点推进证据；若没有真实节点推进而只有底层代码、Contract 或测试增长，立即停止当前路线并收缩到下一节点。
- 每个新增 Contract 字段、状态或基础设施都必须能回答：谁生产、谁消费、当前哪个场景使用、缺少时会造成什么真实故障。没有当前生产者或消费者时，默认进入后续清单，不进入当前实现。
- 已经写入但当前未消费的未来能力不必为了收缩而删除；将其冻结或隔离，不继续扩展，也不把它计入当前完成度，直到真实消费者出现。
- 用户已明确暂缓或搁置的功能不属于当前完成线，不得阻断当前实现、审核、集成或真实验证；只进入后续清单，除非用户重新启用。
- 并行任务必须共同推进同一完成线。默认保持一个实现候选、一个只读审查和一个集成分支；只有边界互不冲突且能直接解除当前链阻断时才扩大并行。
- 每个长任务工作日结束前形成至少一个可识别集成候选：固定 HEAD、验证结果、已实现能力、未实现能力和下一真实节点。不得让多个局部分支持续增长而长期不集成。

## 审核停止线与问题等级

- 候选默认只走：实现→一次独立审核→修复确认的阻断问题→一次定向复核→冻结集成。复核后不得重新扩大全代码面审查。
- 当长任务候选冻结为 P0-only 时，独立审核后只修 P0；P1/P2 只记待办，一次定向复核确认 P0 根因后立即冻结集成，不得开启新的整面审核。
- P0 是会造成串账号或越权、重复不可逆动作、丢失当前链数据、破坏权威数据或使当前链无法启动／恢复的问题，必须阻断。
- P1 是恢复能力、资源上限、运营可用性或当前阶段非主路径的问题；只有当前完成线确实依赖它时才阻断，否则记录欠账。
- P2 是未来扩容、优化或极端规模问题，只记录，不阻断当前链。
- 连续两轮仍出现同一类阻断时，停止局部补丁和整面复审，回到整体状态机、权威数据流或任务拆分重新设计；完成根因修复后只验证该根因及必要回归。
- 独立审核只检查候选约定的范围和阻断等级。新发现的非阻断问题进入待办，不能借审核自动扩大当前产品范围。

## 选择与问题相称的架构

- 小修复保持改动局部，不为一个分支引入整套框架。
- 新能力先明确输入、输出、错误、取消／超时和关键不变量，再选择实现结构。
- 业务规则、格式、范围、预算和状态转换交给确定性代码；模型或 Agent 负责适合认知判断的部分，并显式表达不确定性。
- UI、存储、平台对象和外部供应商细节不要渗入可复用领域逻辑。
- 不为尚不存在的第二消费者、模块市场、计费体系或正式用户数据提前建设复杂治理。

当能力确实需要跨软件复用时，再采用以下可选分层：

```text
稳定 Contract + 可复用 Core + 可选 Port／Provider Adapter + Product Adapter + 相关测试
```

- Core 不依赖当前产品 UI、数据库表、任务对象、Host 私有接口或 Product Adapter。
- Port 由 Core 的真实需要定义；Provider Adapter 连接模型、云服务或系统工具。
- Product Adapter 只做当前产品映射和接线，不复制核心算法。
- 普通单产品功能不强制套用完整分层；结构复杂度必须由真实复用或隔离需求证明。

进一步原则见 [设计原则](references/design-principles.md)。

## 实现真实能力

- 禁止用 TODO、固定假响应、空壳 Provider、只转发参数的接口或 Mock 数据声称完成。
- 优先保留已验证且正确的核心行为，修复时锁定现有 Contract 和回归边界。
- 将供应商私有字段、原始响应和错误转换为项目稳定语义，不泄漏到公共 Contract。
- 对外部调用设置合理超时、有限重试和取消；取消后停止继续发起工作。
- 密钥从环境变量或未纳入版本控制的受限配置读取；禁止写入仓库、日志、命令输出或交付包。
- 处理不可信输入时，在读取／解码／流式处理期间执行大小和资源预算，不先无界缓存再判断。
- 对评审意见先用 Contract、代码或最小复现确认。确认缺陷后，先区分需求、Contract、设计、实现、测试、环境或证据问题；不得只为让评审或测试变绿而修改断言、吞掉异常或增加无依据特判。
- 同一症状在一次修复后再次出现，或修复开始跨层堆叠例外、绕过关键不变量或状态机时，停止继续打补丁；回到 Contract、状态转换和数据流形成一个连贯的根因修复，再用最小复现和必要回归验证。

涉及文件内容、Base64、重复判断或暂存时读取 [内容边界](references/content-boundaries.md)。涉及子进程、浏览器、编译器、FFmpeg、Python、OCR 等工具时读取 [外部工具与进程边界](references/external-tools.md)。

## 验证真实且相关的内容

- 先运行与改动直接相关的单元、Contract、Adapter、集成或构建验证；跨包和高影响改动再扩大范围。
- 修复测试失败后，只重跑受影响用例和必要回归；精确源码与产物未变化时不要重复全量测试。
- 声称真实模型、API、数据库、工具、服务器或手机可用时，至少做一次对应真实试运行；Mock 只证明本地分支。
- 构建成功不等于已安装；本地集成不等于生产部署；静态检查不等于真实端到端。
- 测试本身失败时，先区分产品缺陷、测试夹具缺陷和环境阻断，不能为了绿色结果篡改 Contract。
- 验证投入与风险相称，不默认生成独立 evidence、全量哈希、SBOM、多轮复审或重复状态文档。

## 部署和验收分层报告

分别标注：

- 源码已实现；
- 相关测试／构建已通过；
- 交付物已生成；
- 已部署到目标环境；
- 已完成真实端到端；
- 已被用户或验收门正式接受。

只报告实际达到的层级。若被磁盘、权限、DNS、证书、外部账号、设备操作或真实数据阻断，完成其余安全工作后，给出最短恢复条件，不把阻断写成已完成。

## 完成判断

交付前确认：

- 用户要求的功能或修复是否真实完成；
- 调用者是否依赖稳定入口而非内部实现偶然性；
- 空值、缺字段、异常、取消、超时和资源边界是否按风险处理；
- 是否保留了任务外的用户改动和系统边界；
- 相关测试、构建或真实试运行是否足以支持当前声明；
- 是否清楚列出尚未部署、未真机、未生产签名或未真实数据验证的部分；
- 长任务的最终候选是否仍符合当前基线；每个已确认的评审问题是否已有根因修复和对应验证，未解决项是否作为限制报告；
- 是否避免了与结果无关的重复测试、文档和治理。

最终简洁报告结果、关键文件、相关验证和剩余限制。常见越界与返工模式见 [常见陷阱](references/pitfalls.md)。
