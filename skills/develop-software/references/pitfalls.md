# 常见陷阱

## 把历史治理当成默认门禁

旧任务书、冻结提交、独立 evidence、全量哈希、SBOM 或多轮审核不能自动阻止当前普通开发。只在当前任务和风险确实需要时使用。

## 把评审当成修改授权

用户只要求 review、audit、诊断或解释时保持只读。发现问题不等于获得修复、提交、部署或外部写入权限。

## 用占位或 Mock 冒充完成

空壳接口、TODO、固定结果和假 Provider 不能证明真实能力。Mock 只证明受控分支；真实模型、数据库、服务器、工具和设备需要对应试运行。

## 为简单问题套复杂架构

不是所有功能都需要 Contract／Core／Port／Adapter 全套分层。复杂度应由复用、隔离、替换或测试需求证明。

## 产品细节污染稳定能力

页面状态、数据库表、任务对象、供应商字段和 Host 私有接口不应进入可复用领域逻辑。需要复用时通过 Adapter 映射。

## 无界等待、缓存和重试

外部进程、网络调用和锁必须有合理超时与有限重试；流产生期间执行预算；取消后不再发起新工作。

## 固定本机路径和泄露秘密

不要写死用户目录、临时目录或开发机工具路径。密钥、口令和连接串不能进入仓库、日志、命令输出或公开产物。

## 重复验证代替判断

精确源码和产物未变化时，不要为了留痕重复全量测试。修复后运行受影响用例和必要回归，高风险变化才扩大范围。

## 过度声称状态

源码完成不等于构建、安装、部署、真实端到端或正式验收。只报告已由证据支持的层级和剩余限制。
