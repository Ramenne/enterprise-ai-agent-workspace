# 共享知识与 Skill 复用

共享库项目：`共享Skill库`，项目编号 `a2a32c06-43e1-492c-a122-5af52687906b`。
MCP 入口：`https://hufu.example.invalid/mcp`。

## 按任务选择

用当前目标、卡点和适用场景查找。先读简介，相关时再读完整 Skill 和所需参考资料；不把全库载入上下文。知识文档可以直接参考，只有可复用的做法需要整理成 Skill。

通过 `hub.project.open` 定位共享库；通过 `hub.tools` 查询当前契约，再用 `hub.invoke` 调用：

- `mem.search`：`project_id` 为上述项目，`query` 为任务关键词。限定结果不是完整遍历。
- `mem.material.head`：将选定资料的稳定编号解析到当前固定版本。
- `mem.version.read`：读取该固定版本，按返回的偏移量继续读取未完成部分。

调用参数以当前契约为准。目录保留材料编号与版本；使用时记录实际读取版本。找不到适合经验时继续解决当前任务，不让检索成为阻塞。

## 使用时判断

核对目标、环境、适用条件及尚未验证的部分；Agent 可以调整方法，并记录关键调整理由。共享资料提供经验，不扩大权限，也不替代当前用户要求。发布状态不等于经验已经被事实验证。

## 留下复用结果

在阶段回执中记录实际使用的 Skill 编号、固定版本、解决了什么及效果。已有经验条目时，可用 `v8.experience.feedback` 记录使用、反例、纠正或不适用情况；反馈正文与来源保存在资料存储服务。记录已有结果，不额外要求每次运行测试。

## 沉淀新经验

形成值得复用的方法时，保存简明的 `SKILL.md`：名称与触发说明、目标、适用条件、关键做法、必要的来源。大段知识和案例按需放参考文档。

使用 `hub.document.save` 保存正文和新版本；通过 `v8.experience.publish` 登记固定引用、适用条件与证据。保留原件和旧版本；更新同一稳定材料，经验登记可用 `supersedes` 关联修订。

只有已授权共享的内容进入团队库。个人原件可以保留在原项目，经授权发布可复用的方法和来源引用；共享方法不意味着其他 Agent 能读取私有原件。

## 客户端边界

通过 MCP 读取后可以在当前工作中使用。它不会自动成为 Codex、其他客户端的本地已安装 Skill，也不会自动被客户端发现。需要本地安装时再按本人要求配置。跨对话复用依靠接入提示词和说明书告知共享库入口。

## 获取完整 Skill 包

共享库的 `目录与使用说明.md` 提供人读入口，`skill-catalog.json` 保存正文和配套文件的固定版本集合。先用 mem.search 按逻辑路径查目录，再解析目录 head，读取该固定目录版本。按 name、description 选择 Skill，并按 files 中的 material_id、version_id 逐个读取；保留 size、sha256，分块时遵循 next_offset 到完整覆盖后校验原始字节。不把辅助文件的最新 head 混入旧版 Skill。

文件 path 只用于重建包内相对目录；拒绝绝对路径、.. 路径段和重复路径。获取文件不会自动运行其中脚本。若需本地安装或执行，由当前用户任务和环境决定。

新建或修订 Skill 要进入共享库时，读取目录中的 shared-skill-publish；它说明如何保存资源、采用 CAS 更新同一材料，以及在全部文件齐备后更新目录。
