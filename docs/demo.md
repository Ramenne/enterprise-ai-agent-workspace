# 本地交互展示

在仓库根目录运行：

```bash
npm run demo
```

打开 http://127.0.0.1:4173 。需要第二个同时运行的窗口时，使用 `node demo/server.mjs 4174`。

账号 `demo`，口令 `demo-only`。无需 npm install、数据库或 API Key；需要 Node.js 20+。

这是独立重绘的交互原型，帮助理解产品流程。它与原始前端分别存放；登录只切换浏览器会话状态，页面不调用后台或模型。全部会话、订单、成员、任务及图表指标均为模拟，不作为业务成果。

八个页面：平台总览、信息与工作关联、工作与成果、资料与版本、工具库、员工协作、身份与权限、平台结构。

建议沿一条工作链展示：

1. 总览查看平台能力地图和六步流程，点击模块进入对应页面。
2. 在信息页将成员反馈关联到示例工作，再到工作页核对关联状态。
3. 在资料页切换v1和v2，观察“查看最新版本”与“工作已采用版本”的区别。
4. 在工具库搜索“恢复”或“工作流”，筛选知识、Skill等六类模块，阅读来源、条件、限制、输入输出与步骤。
5. 采用知识或选用方法后，到工作页核对本页关联；其他模块只生成合成回执。
6. 在员工协作、权限和结构页理解入口、职责与范围。角色切换只改变本页合成视图，不签发真实权限。

刷新会清空内存中的关联和选用记录；退出会移除本标签的演示登录状态。知识与Skill不会写入真实服务，不会安装或执行方法包。

页面采用浅色布局、侧栏导航、状态标签和内容卡片。演示不是原线上 UI 截图，不证明真实鉴权、LLM推理、消息收发或数据库迁移已经通过验收。
