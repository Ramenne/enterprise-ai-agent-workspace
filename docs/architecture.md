# 产品链路与代码导航

完整结构、信息接收方式、对象关系和各模块源码见 [平台架构详解](platform-architecture.md)，工具库六模块与使用路径见 [工具库详解](tools-library.md)。本页保留简短导航。

## 工作链路

1. 成员或Agent经员工客户端、MCP等入口提交需求、反馈、阶段记录和资料引用。
2. V8将记录、资料与具体工作组织关联；识别相同主题与同一工作的差异，保留阶段状态和协作关系。
3. 人与Agent推进工作；工具调用由身份、权限和执行范围约束，Worker承接需要持续推进的执行。
4. 资料存储服务管理资料及版本，工作引用固定成果作为后续依据；员工客户端承接成员消息、工作入口与通知。
5. 回顾时提炼适用经验，并将可重复执行的方法组织为Skill；后续工作通过检索、判断适用条件和采用进行复用。

上述是产品组织方式。并非每次信息进入、关联、经验提炼和采用都自动完成，也不保证任何Skill能自动完成任意任务。

## 快照关系

hub与worker保留各自导出时的共享服务代码；v8与storage是独立导出目录。不要假定同名文件内容完全一致，也不要直接把各目录SQL依次执行到现有生产库。

公开整理中将内部UUID映射为一致的示例UUID，将历史存储时钟数据置空，保留结构和实现逻辑。部署需要建立自己的身份、项目、存储及工具登记。
